# 妖怪大戦

ブラウザで遊ぶ、妖怪 6 体どうしのリアルタイム対戦（人 vs CPU・人 vs 人）。1 ファイルの HTML で動く。
本家（妖怪ウォッチ2）の対戦画面の配置をまねている。妖怪は民話の妖怪をもとにしたオリジナルが中心で、流行りの編成に出てくる妖怪は本家の名前・本家に寄せた見た目。本家との差と埋めたところは [docs/GAP.md](docs/GAP.md)。

- 398 体すべてに **固有の特性** と **3D モデル**（アイコンも同じ 3D モデルをその場で撮った絵）
- **対人戦**（オンライン。サーバー不要の WebRTC、または同じブラウザの 2 画面）。持ち物（装備）は対人戦でも効く。回復などのアイテムはなし
- 奥義のパワーチャージ（スキルチェック）・被弾・奥義・回復・とりつきに光と衝撃波のエフェクト
- 編成画面の **流行りの型**：本家の通信対戦で流行った編成 7 つ（ブシニャン特化・赤鬼特化・ミツマタノヅチ特化・黒鬼ゾンビなど）をプリセットで入れられる。出てくる妖怪は本家の名前・見た目（出典と中身は [docs/PRESETS.md](docs/PRESETS.md)）。ひとまか仙人・あせっか鬼は新しく足した
- 奥義は本家と同じく、タッチアクション（スキルチェック）を最後まで終えると発動。ためや出来の良し悪しで威力は変わらない
- ホイール（サークル）回しは指に遅れずについていき、離すと 60° ごとにぴたりと止まる
- **奥義のモーション**を全員に：10 種の振り付け（跳び叩きつけ・連撃・回転突き・光線・天降らし・地鳴らし・竜巻・瞬影斬・祝福の光・しなり打ち）を奥義の種類・属性・動きの癖で選び、回数・高さ・回転は 1 体ずつ変える
- 当たった瞬間のヒットストップ（ふつう 0.06 秒・会心 0.26 秒・撃破 0.24 秒・奥義の決め 0.2 秒前後）
- ダメージの数字（ふつう・受けた・弱点・会心で見た目がちがう）。会心は金の大きな数字・放射線・ヒットストップ・専用の音。攻撃が続くと「○ HIT」と合計
- 本家の **装備 74 種**・**魂**・**たべもの／牛乳・ジュース／おふだ／漢方／みがわり人形**
- 本家の **パワーチャージ 4 種**・**おはらい 5 種**・右下の **アイテム**
- 本家の **性格 12 種**（短気・荒くれ・れいせい…動じない）と前半の **まじめさ**（超まじめ〜超ずぼら）。性格ボーナスも本家どおり
- 編成画面で 3D モデル・能力値（装備こみ）・特性・好物を確かめ、性格／持ち物（装備・魂）／アイテムを選ぶ。選ぶ画面は種類でしぼりこみ・効果の大きい順などに並べかえができる。出陣前にまとめて確認

## 遊ぶ

- オンライン版：<https://s70rm3892.github.io/yokai-taisen/>（GitHub Pages）
- 1 ファイル版：[Releases](https://github.com/s70rm3892/yokai-taisen/releases) の `yokai-taisen.html` をダウンロードしてブラウザで開く

`main` に push すると GitHub Actions（`.github/workflows/release.yml`）がテスト → ビルド → Pages へ公開し、
`package.json` の version（例 1.0.0 → `v1.0.0`）の Release がまだ無ければ `yokai-taisen.html` を添付して作る。
版を上げるときは version を上げて main に入れる。同じものを `gh-pages` ブランチにも置く。
Pages を使うには、初回だけリポジトリの Settings → Pages で Source を「GitHub Actions」にするか、「Deploy from a branch」で `gh-pages` / `(root)` を選ぶ。

## 作り方

```sh
npm install
npm run build        # dist/index.html（これ 1 つで遊べる）
npm test             # 対戦ロジックを CPU どうしで数百戦させる＋全員の特性・装備を確かめる
node tests/smoke.mjs       # ブラウザで編成→対戦まで進めてスクリーンショット（dist/shots）
node tests/battle_ui.mjs   # アイテム・パワーチャージ 4 種・おはらい 5 種を実際に操作
node tests/pvp.mjs         # 対人戦を 2 ページで決着・再戦・切断まで（同じブラウザの 2 画面方式）
node tests/pvp_rtc.mjs     # 対人戦の WebRTC 接続（招待コード → 返事コード）
node tests/presets.mjs     # 流行りの型：ルールを満たすか・持ち物が付くか・押して対戦できるか
node tests/pickers.mjs     # 性格・持ち物・アイテムの選ぶ画面（しぼりこみ・並べかえ・選んだものが入るか）
```

## 対人戦

編成画面の左「対人戦（人 vs 人）」から。いまの編成（性格・持ち物（装備）こみ）で戦う。持ち物（呪言の刀など）は対人戦でも効き、名札とログに出る。**回復などのアイテムはなし**（右下は「アイテムなし」）。

- **部屋を作る**：招待コードを作って相手に送る（LINE など）→ 相手の返事コードを貼ると始まる
- **部屋に入る**：相手の招待コード（または招待リンク `…#join=コード`）を貼る → できた返事コードを相手に送る
- **この端末で 2 画面**：同じブラウザで 2 つのタブを開き、同じ 4 けたの部屋番号で作る・入る

通信は WebRTC のデータチャネルで、ゲームのサーバーは使わない（接続の下準備に公開の STUN サーバーだけ使う）。
おたがいの回線によっては（会社・学校のネットワークや一部のモバイル回線）つながらないことがある。

しくみ：部屋を作った側だけが対戦を進め、1 tick（50ms）ごとに「その tick の両者の入力」を送る。
対戦ロジックは同じ入力なら必ず同じ結果になるので、入った側も同じ入力を流して同じ対戦を再現する（5 秒ごとに状態をまるごと送って合わせ直す）。
入った側の画面は左右を入れ替えて見せるので、どちらも自分が手前になる。「あわせろ！」は押した瞬間に見えていた tick で判定する（通信の遅れで不利にならないように。1 秒以内まで）。

`dist/index.html#gallery=1`〜`#gallery=10` で全員の 3D モデルを 40 体ずつ並べて見られる。

## ファイル

- `src/template.html` … 画面の枠と CSS
- `src/game.js` … もとの公開版を読みやすく整形したもの（three.js を含む）。`/*@@include …@@*/` の場所に `src/ext/` を差し込む
- `src/ext/honke_items.js` … 本家の装備・アイテム（出典つき）
- `src/ext/traits.js` … 固有特性（一族ごとの効果 × 役割ごとの主効果）と魂、好物、元祖軍／本家軍
- `src/ext/loadout.js` … 性格（本家の 12 種・まじめさ・性格ボーナス）と装備から対戦の能力値をまとめる
- `src/ext/engine_fx.js` … 特性・装備・アイテムの効果を対戦ロジックへ
- `src/ext/engine_minigames.js` … パワーチャージ 4 種・おはらい 5 種の判定と CPU
- `src/ext/models3d.js` … 3D モデル（一族ごとの体つき）・編成画面の回転プレビュー・3D モデルから撮るアイコン
- `src/ext/builder_ui.js` … 編成画面の確認・選択・出陣前の確認
- `src/ext/battle_ui.js` … 対戦画面のアイテムとタッチアクション（スキルチェックのエフェクトこみ）
- `src/ext/fx3d.js` … 3D の対戦画面のエフェクト（光の粒・衝撃波・光の柱・斬撃・チャージのオーラ・花びら）
- `src/ext/pvp.js` … 対人戦（通信・ロビー・同期）
- `src/ext/presets.js` … 流行りの型（プリセット）
- `src/ext/roster_plus.js` … 足した妖怪（ひとまか仙人・あせっか鬼）と新しい特性
- `src/ext/honke_names.js` … 流行りの編成に出てくる妖怪の本家の名前・見た目・ランク
- `src/ext/ult_motion.js` … 奥義の振り付け 10 種と、全員への割り当て
- `tools/build.mjs` … 1 ファイルにまとめる（esbuild で圧縮）
- `tools/check_names.mjs` … 追加した名前が、圧縮済みの短い名前とぶつからないか調べる
