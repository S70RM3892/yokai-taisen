# 戦闘仕様書 v0.2（P1 実装用）

> このドキュメントが戦闘コアの**唯一の正**。実装とズレたら、実装かこの文書のどちらかを直す。
> 数値はすべて**たたき台**。P1 のシミュレーターで回して調整する前提。

---

## 0. 実装の絶対ルール

1. **決定論**：同じ初期状態 + 同じ入力列 → 必ず同じ結果。
2. **整数演算のみ**：浮動小数点禁止。倍率は **‰（千分率, 1000 = 1.0倍）** で持つ。割り算は `Math.floor` で切り捨て。
3. **乱数なし（v0.1）**：ダメージの揺れ・クリティカル・なまけは入れない。運の要素はゼロから始めて、必要なら後で足す。
4. **固定ティック**：1 tick = 50ms（**20 tick/秒**）。すべての時間は tick で数える。
5. 戦闘コアは描画・通信・時計に依存しない純粋なライブラリ。`step(state, inputs) -> state` の形にする。

## 2. ユニットのステータス

| ステ | 略 | 範囲の目安 | 役割 |
|---|---|---|---|
| 体力 | HP | 300〜600 | 0 で戦闘不能 |
| 力 | ATK | 60〜140 | 通常攻撃のダメージ |
| 妖力 | SPA | 60〜140 | 術・回復・奥義（術系）のダメージ |
| 守り | DEF | 60〜140 | 受けるダメージを減らす |
| 素早さ | SPD | 50〜140 | 行動ゲージの溜まる速さ |
| 妖気速度 | SGR | 1〜6（ランク） | 妖気ゲージの溜まる速さ（原作の6段階に合わせる） |

他に **種族**（6種）、**属性の相性**、**性格（行動サイクル）**、**呪付の技**、**奥義** を持つ。

### 2.1 育成 ― 厳選なし・自由調整

原作（YW2）では、ステータスの差がこうやって決まっていた。
- 個体値：40pt が5つのステに割り振られる（HP だけは2倍に数える）。捕まえた時点で決まっていて、いい個体を引くまで何度もやり直す「厳選」が必要だった。
- 性格：行動の傾向と、合計最大 +20 のステ補正を決める。変えるにはアイテムが必要だった。

本作では **厳選をなくす**。運で決まる要素も、何度もやり直す作業もない。

| 原作の要素 | 本作 |
|---|---|
| 個体値（ランダム） | **廃止**。同じユニットの素のステータスは全員同じ |
| 努力値・性格のステ補正 | **努力ポイント** に一本化。プレイヤーが自由に割り振る |
| 性格（行動の傾向） | **性格** ＝ 行動サイクルを選ぶ。自由に変えられる（§4.2） |
| レベル | 対戦では関係なし（全員同じ条件） |

**努力ポイントのルール**
- 1体につき **40 pt**（原作の個体値の合計に合わせた）。
- 1つのステに入れられるのは **最大 20 pt**。
- 1 pt あたり：ATK・SPA・DEF・SPD は **+1**、HP は **+4**（原作の「HP は2倍」と同じ考え方。本作は HP の桁が大きいので4倍にした）。
- 妖気速度（SGR）には入れられない。
- 例：鎌鼬（ATK 125・SPD 140）に「ATK 20・SPD 20」→ ATK 145・SPD 160。

**変更について**
- 編成画面で **いつでも・何度でも・無料で** 変えられる。アイテムも待ち時間もいらない。
- 対戦が始まったら変えられない。
- **相手に見えるもの**：ユニットと性格は対戦前の編成公開で見える（行動サイクルは試合中に画面に出るので、隠す意味がない）。**努力ポイントの配分は見えない**。「速さに振ったか、硬さに振ったか」を読むことが、運ではない読み合いになる。

## 3. 時間の流れ（1 tick の処理順）

**処理順は固定。変えるとリプレイが壊れる。**

1. **入力の処理**（両プレイヤーの入力を P1 → P2 の順に）
   - 回転 → 標的 → アイテム → 奥義（構え開始／解放／キャンセル）
2. **構えの進行**（スキルチェックのタイマーを進める）
3. **ゲージの加算**（前衛のみ：AG・SG）
4. **行動の解決**：AG ≥ 1000 の前衛ユニットを「AG が大きい順 → SPD が高い順 → P1 が先 → スロット番号が小さい順」に並べ、1体ずつ行動させる
5. **継続効果**（毒などのダメージ、呪付の残り時間を減らす）
6. **浄化の進行**（後衛）
7. **戦闘不能の判定** → **勝敗の判定**

## 4. 行動ゲージ（AG）と自動行動

### 4.1 溜まる速さ
```
1 tick あたりの AG 増加 = 10 + floor(SPD / 5)
AG が 1000 以上になったら行動し、AG -= 1000（余りは次回に持ち越す）
```
| SPD | 増加/tick | 1回の行動までの時間 |
|---|---|---|
| 50 | 20 | 2.50秒 |
| 100 | 30 | 1.67秒 |
| 140 | 38 | 1.32秒 |

- **後衛では AG は増えないが減らない**（凍結）。回して前に出ると、止まっていたところから再開する。
- **開始時の前衛にはボーナス**：開始時の AG = 300（原作の初期前衛補正に相当）。後衛は 0 から始まる。

### 4.2 性格（行動サイクル）
原作では、性格で自動行動の傾向が決まっていたが、実際に何をするかはランダムで、運負けの原因だった。本作では **性格＝決まった順番の行動サイクル** にする。

- 5つの行動をこの順番でくり返す。
- **どのユニットにも、下の8つの性格のどれでも自由に付けられる**（§2.1 と同じで、いつでも無料で変えられる）。
- **サイクルの現在位置は画面に出す**。→ 「次に呪付が来るぞ」が読める。これが読み合いの素材になる。
- 選べない行動が来たときは、通常攻撃に置き換わる（例：呪付をかける相手がいない）。サイクルは1つ進む。

| 性格 | サイクル | 攻 | 術 | 守 | 呪 | ねらい |
|---|---|---|---|---|---|---|
| 猛攻 | 攻 攻 攻 術 攻 | 4 | 1 | 0 | 0 | 物理で殴り続ける。呪付は使わない |
| 術重 | 術 術 攻 術 呪 | 1 | 3 | 0 | 1 | 術アタッカー向け |
| 均衡 | 攻 術 呪 攻 守 | 2 | 1 | 1 | 1 | 何でもできる。基準になる性格 |
| 奔放 | 術 攻 攻 呪 術 | 2 | 2 | 0 | 1 | ATK と SPA が両方高いユニット向け |
| 妨害 | 呪 攻 術 呪 守 | 1 | 1 | 1 | 2 | デバフを多く入れる |
| 献身 | 呪 術 守 呪 術 | 0 | 2 | 1 | 2 | バフ・回復の支援役 |
| 堅守 | 守 攻 術 守 呪 | 1 | 1 | 2 | 1 | 壁役。前にいる時間を長くする |
| 慎重 | 攻 守 術 呪 攻 | 2 | 1 | 1 | 1 | 均衡の守りが早く来る版 |

- 同じ性格でも、ユニットによって「術」「呪」の中身が違う（`UNITS.md`）。
- 「猛攻」は呪付を捨てる代わりに火力が出る。「献身」は殴らない。**性格の選び方そのものが編成の戦略になる**。
- 8つで足りるかどうかは P1 のシミュレーターで見る。「サイクルを完全に自作できる」ようにするかは、強すぎる組み合わせが出ないか確認してから決める。

### 4.3 行動の種類
| 行動 | 効果 |
|---|---|
| 攻（通常攻撃） | 物理ダメージ。威力 30、ATK を参照 |
| 術 | 属性ダメージ。威力はユニットごとに決まる（35〜50）、SPA を参照 |
| 守（ガード） | 次の自分の行動まで、受けるダメージが 500‰（半分） |
| 呪（呪付） | ユニット固有の呪付をかける（§7） |

### 4.4 ねらう相手
1. 標的（§8）が敵の前衛にいれば、その敵を狙う
2. いなければ、**敵の前衛で HP の割合が一番低い** ユニットを狙う（同じならスロット番号が小さい方）

## 5. ダメージの計算

```
基本値     = floor(攻撃側のステ × 威力 / 100)
守り補正後 = floor(基本値 × 100 / (100 + 防御側の DEF))
最終       = 守り補正後 × 相性‰ × 陣‰ × 呪付‰ × ガード‰ × 奥義の出来‰ を順番にかけて、1回ごとに /1000 して切り捨てる
最低 1 ダメージ
```
- 例：ATK 100・威力 30 → 基本値 30 → DEF 100 なら 15 ダメージ。
- 目安：通常攻撃 1 回で最大 HP の 3〜5%。1試合 **2〜3分** を目標にする（シミュレーターで確認する）。

### 5.1 属性（6種）
火・水・雷・土・氷・風。ユニットごとに **弱点 1 つ・耐性 1 つ** を持つ（無しでもよい）。
| 相性 | 倍率 |
|---|---|
| 弱点 | 1500‰ |
| ふつう | 1000‰ |
| 耐性 | 500‰ |

通常攻撃は無属性（相性の補正なし）。

## 6. 妖気ゲージ（SG）と奥義 ― スキルチェック

### 6.1 溜まる速さ
| 妖気速度ランク | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| SG 増加/tick（前衛のみ） | 4 | 5 | 6 | 7 | 8 | 10 |
| 満タンまで | 12.5秒 | 10秒 | 8.3秒 | 7.1秒 | 6.25秒 | 5秒 |

- 攻撃を受けると SG が増える：`floor(受けたダメージ × 500 / 最大HP)`
- **開始時の SG は 500**（半分）。開幕の奥義の撃ち合いだけで試合が決まらないようにする。
- 最大 1000。後衛では凍結。

### 6.2 構え（奥義を撃つまでの流れ）
SG が 1000 の前衛ユニットに対して、プレイヤーが「奥義」を入力すると **構え** に入る。

```
[構え開始] → 溜めフェーズ（0〜2秒、プレイヤーが決める）→ [解放入力] → タイミング判定 → 奥義発動
```

1. **構えているあいだ、そのユニットの AG は凍結**。自動行動しない。
2. **構えは相手の画面にも出る**（どのユニットが構えたか・溜めの段階）。相手は「狙われそうなユニットを回して逃がす」ことで対応できる。
3. **溜め**：構えている時間が長いほど威力が上がる。
   | 溜め時間 | 溜め倍率 |
   |---|---|
   | 0〜0.5秒（0〜9 tick） | 1000‰ |
   | 0.5〜1.0秒（10〜19 tick） | 1100‰ |
   | 1.0〜2.0秒（20〜40 tick） | 1200‰ |
   | 2秒を超えた | **自動で解放**（タイミング判定は Miss 扱い） |
4. **タイミング判定**（スキルチェック）：溜めているあいだ、画面のリングにカーソルが 0.8 秒周期（16 tick）で回る。解放入力をした瞬間の位置で判定する。
   | 判定 | 当たり範囲 | 出来の倍率 |
   |---|---|---|
   | Perfect | 16 tick 中 2 tick | 1150‰ |
   | Good | Perfect の前後 2 tick ずつ | 1000‰ |
   | Miss | それ以外 | 800‰ |
   - 判定はサーバ側の tick で行う（入力に tick 番号をつけて送る）。
5. **狙う相手**：解放した瞬間の標的 → 無ければ §4.4 と同じルール。解放の瞬間に相手が回して前衛からいなくなっていたら、新しく前にいるユニットに当たる。

### 6.3 構えのキャンセル ―「チャージ待ち」を正式な仕様にする
原作（YW2）では、必殺チャージの開始とキャンセルをくり返すと行動順に割り込めるバグがあった。上級者はこれを使って、特定の2体に交互に行動させ続けていた（無限攻撃）。
本作では、この「**行動のタイミングを自分で調整する**」面白さだけを正式な仕様にして、無限ループはできないようにする。

- 構えを **キャンセル** すると、SG は 1000 のまま残り、AG の凍結も解ける。
- **キャンセルしたユニットは 3 秒（60 tick）構えられない。**
- → 使い道：わざと行動を遅らせる。例：「相手の呪付が来るまで待ってからガードを出す」「味方のバフ呪付が入るまで奥義を待つ」。

### 6.4 奥義の種類（ユニットごとに1つ）
| 種類 | 例 |
|---|---|
| 単体大ダメージ | 威力 150、SPA 参照、属性つき |
| 全体ダメージ | 敵の前衛全員に威力 70 |
| 回復 | 味方の前衛全員の HP を `SPA × 60%` 回復 |
| ガード崩し | 威力 100、ガードを無視する |
| 呪付の強化版 | 呪付の効果 ×2・時間 ×1.5 |

- 威力は表のとおり。**参照するステータス（ATK か SPA か）と属性はユニットごとに決める**（[`UNITS.md`](./UNITS.md)）。
- 回復系の奥義にも「出来」の倍率をかける。

## 7. 呪付と浄化

### 7.1 呪付
- 行動サイクルで「呪」が来たときにかける。
  - **敵へのデバフ**：敵の前衛の1体にかける（§4.4 と同じルールで選ぶ）
  - **味方へのバフ**：味方の前衛のうち、効果が一番活きるユニットにかける（攻撃バフなら ATK が一番高い味方。原作の仕様に合わせた）
- 効果時間は **15 秒（300 tick）**。同じユニットにかけられる呪付は1つ。後からかけたもので上書きする。
- **後衛に回しても時間は減らない**（凍結）。つまり、デバフは浄化しないと消えない。

### 7.2 呪付の効果（v0.1）
| 名前 | 種類 | 効果 |
|---|---|---|
| 鈍重 | デバフ | AG の増加が 50% |
| 衰弱 | デバフ | 与えるダメージが 700‰ |
| 脆化 | デバフ | 受けるダメージが 1300‰ |
| 蝕毒 | デバフ | 1秒ごとに最大 HP の 2% のダメージ |
| 封気 | デバフ | SG が増えない |
| 鼓舞 | バフ | 与えるダメージが 1300‰ |
| 堅護 | バフ | 受けるダメージが 700‰ |
| 疾風 | バフ | AG の増加が 150% |

### 7.3 浄化
- 後衛にいる、デバフのかかったユニットを選んで「浄化」を入力する。
- **2 秒（40 tick）** でデバフが消える。浄化中にそのユニットが前に出たら中断（途中から再開はできない）。
- 同時に浄化できるのは1体まで。
- **浄化するには後ろに下げるしかない → 前衛が弱くなる。** これがこのゲームの一番大事なジレンマ。

## 8. 回転・標的・アイテム

### 8.1 回転
- ホイールを1つ分（60°）、時計回りか反時計回りに回す。**1回回すと 1 秒（20 tick）次を回せない。**
- 構え中のユニットが後衛に行ったら構えはキャンセル扱い（§6.3 と同じ 3 秒の制限がつく）。
- **戦闘不能のユニットもホイールに残る**（原作と同じ）。前衛の枠が戦闘不能で埋まると損なので、回す必要がある。

### 8.2 標的
- 敵の1体をピン留め。切り替えたら 1 秒は次を切り替えられない。
- 標的が後衛に下がったら、ピンは残るが効果なし（前に戻ってきたら再び狙う）。

### 8.3 アイテム
- 1試合 **3 回まで**。使ったら **5 秒** は次が使えない。
- v0.1 はアイテム1種類：**おにぎり相当**＝前衛の1体の HP を最大 HP の 25% 回復。

## 9. 陣（種族ボーナス）

種族（6種、名前は仮）：**猛（タケル）・怪（アヤシ）・剛（ツワモノ）・雅（ミヤビ）・和（ナゴミ）・影（カゲ）**

前衛の3体のうち、同じ種族が2体以上いると発動する（戦闘不能のユニットは数えない）。

| 種族 | 2体 | 3体 |
|---|---|---|
| 猛 | 与える物理ダメージ 1100‰ | 1200‰ |
| 怪 | 与える術ダメージ 1100‰ | 1200‰ |
| 剛 | 受けるダメージ 900‰ | 800‰ |
| 雅 | SG の増加 +1/tick | +2/tick |
| 和 | 回復量 1200‰ | 1400‰ |
| 影 | AG の増加 +3/tick | +6/tick |

回転するたびに陣が組まれたり崩れたりする → 回転にさらに意味が増える。

## 10. 勝敗

- 相手の6体を全員戦闘不能にしたら勝ち。
- **制限時間 3 分（3600 tick）**。時間切れのときは、生きているユニットの **残り HP の割合の合計**（‰）が多い方が勝ち。同じなら引き分け。

## 11. 入力（プレイヤーが送るもの）

```ts
type Input =
  | { t: "rotate"; dir: "cw" | "ccw" }
  | { t: "target"; enemySlot: 0|1|2|3|4|5 }
  | { t: "item"; allySlot: 0|1|2 }        // 前衛の枠
  | { t: "ultStart"; allySlot: 0|1|2 }
  | { t: "ultRelease" }                  // 構えているユニットは同時に1体まで
  | { t: "ultCancel" }
  | { t: "purify"; allySlot: 3|4|5 };    // 後衛の枠
```
入力はすべて `{ tick, player, input }` として記録する → そのままリプレイになる。
